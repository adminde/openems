= Timedata TimescaleDB

OpenEMS Edge implementation for https://www.timescale.com/[TimescaleDB]
(PostgreSQL + TimescaleDB extension). Persists the Channel data of *this* Edge
into a local database, serves historic queries for the local UI and provides
the data for resending to the OpenEMS Backend after connection outages.

NOTE: Schema, write pipeline, read routing, aggregation tiers and the database
prerequisites are shared with the Backend implementation and documented in
https://github.com/OpenEMS/openems/tree/develop/io.openems.shared.timescaledb[Shared TimescaleDB].
This page only covers what is specific to the Edge.

== How it works

=== Write path

Every OpenEMS Cycle (`TOPIC_CYCLE_AFTER_PROCESS_IMAGE`) the component snapshots
the channels of all enabled components:

1. *Persistence filter*: only channels with `AccessMode != WRITE_ONLY` and a
   local `PersistencePriority` at or above the configured minimum (default
   `HIGH`) are persisted at all.
2. *Aggregate flag*: set from the shared `AggregateChannels` include-list.
3. *Buffering*: points collect in an in-memory buffer, flushed to the shared
   write pipeline every *No of Cycles* cycles (default 1) or at 5 000 points,
   whichever comes first. The buffer is also flushed on deactivate.

----
 Cycle (~1 s)
   |
   |  AccessMode / PersistencePriority >= config?  --no-->  (not stored)
   v
 buffer (flush: No of Cycles / 5000 pts)
   |
   v
 shared write pipeline (Tenancy.SINGLE)
----

=== Read path

Routing between raw hypertables and the aggregate tiers is entirely in the
shared bundle. The Edge runs it single-tenant, so queries carry no Edge-ID and
`queryHistoricData(edgeId, …)` simply ignores it.

=== Resend

`getResendTimeranges()` / `queryResendData()` reconstruct the cycles that never
reached the Backend (not-sent marker convention), so `Controller.Api.Backend`
can resend them after an outage.

== Storage profile

Sized for 32 GB eMMC devices. The raw hypertables are the source of truth; the
aggregate tiers accelerate visualization of the aggregate-flagged channels:

|===
| Tier | Resolution | Retention

| `data_*` | every cycle (~1 s) | 7 d (compressed after 1 d)
| `data_1m_*` (aggregate-flagged channels) | 1 minute | 90 d
| `data_15m_*` (aggregate-flagged channels) | 15 minutes | 3 y
|===

The tiers are the compiled profile `Aggregate.of(Tenancy.SINGLE)`.

Keep *Compression Days* at 1 on flash hardware: uncompressed raw data needs
roughly 35x the disk of compressed data, and compressed chunks stay transparently queryable.

== Installation

. Set up the database as described in
  https://github.com/OpenEMS/openems/tree/develop/io.openems.shared.timescaledb[Shared TimescaleDB].
  The default database name on the Edge is `openems`.

. Start OpenEMS Edge via `EdgeApp.bndrun`. The bundle is already part of the runtime configuration.

. Open the Apache Felix Web Console
  (http://localhost:8080/system/console/configMgr).

. Add a configuration for `Timedata TimescaleDB` and set at least Host,
  Database, Username and Password.

On the first activation the bundle creates its schema (hypertables, continuous
aggregates, retention and compression policies) and logs `TimescaleDB connected`.

== Configuration

|===
| Property | Default | Meaning

| Host / Port / Database / Username / Password | `localhost` / `5432` / `openems` / `openems` / `openems` | database connection
| Pool Size / Write Workers | 10 / 4 | HikariCP connections / parallel COPY writers — keep Write Workers below Pool Size so reads always get a connection
| No of Cycles | 1 | Cycles between buffer flushes
| Retention Days | 7 | days to keep raw high-resolution data
| Compression Days | 1 | days before raw chunks are compressed columnar
| Persistence Priority | `HIGH` | minimum local `PersistencePriority` a Channel needs to be persisted at all
|===

== Debugging

The component logs `TimescaleDB connected` on successful activation and the
connection error otherwise. The shared pipeline logs queue depth and drain rate
on its own cadence, and a fine-grained query on a channel outside the aggregate
include-list logs the one-time
`WARN … consider adding it to AggregateChannels`.

NOTE: The shared `WriteHandler` exposes `debugLog()` (queue fill level, total
written points) and per-hypertable sizes, but the Edge implementation does not
surface them yet — unlike the Backend implementation.
